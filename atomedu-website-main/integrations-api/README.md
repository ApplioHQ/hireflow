# Graph integrations Worker

The production Worker is `https://atom-integrations-api.archimedes-api1.workers.dev`. Its public, read-only graph JSON download powers Dropbox Saver. GitHub and Notion one-shot OAuth exports have been tested live and are available. Google Drive graph export now uses Google Identity Services in the browser and sends the selected graph JSON directly to the Drive API, without this Worker receiving or storing a Google access token. The former server-side Drive OAuth routes below are retained but are not used by the public Proof Lab UI. Zapier remains a manual JSON handoff. Dropbox Saver fetches the user-approved public graph file URL directly; anyone with that URL can read its graph content.

The GitHub OAuth app is owned by the `Atom-edu` GitHub organization and has client ID `Ov23liLNNtv48fHf3n2A` (public). It requests only the `gist` scope, which can read and write a user's Gists, not repositories. Its callback is the exact Worker URL `/api/integrations/oauth/github/callback`, with wildcard matching and device flow disabled. Gists created by the route are **unlisted, not private**. The GitHub client secret is not in this repository. Notion uses an OAuth connection installable in any workspace with a page picker; the user must supply a destination page URL and select that same page during authorization.

The Dropbox app is `atomEDU Proof Lab`, with public app key `ajyniy3x7a5h1yl`. Its registered Saver domains are `atom-edu.org` and `localhost`. The app secret is not used or stored in this codebase. The Saver supports up to 24 expressions and a bounded URL; larger graphs retain a local JSON download option.

## Setup

1. The current `wrangler.jsonc` deploys on `workers.dev`. The public Proof Lab uses its download and one-shot GitHub/Notion routes. GitHub and Notion client secrets plus `SESSION_SECRET` belong only in Cloudflare secrets, never in source or `vars`.
2. The Google Cloud project `atomedu-proof-lab` has the Drive API enabled, an external production OAuth app, only `https://www.googleapis.com/auth/drive.file`, and a Web client with JavaScript origin `https://atom-edu.org`. Its public client ID is used in the browser. No Google client secret is required or stored by the current Drive button. Google Search Console verified the atomEDU URL-prefix property; Google may take time to reflect that in branding verification.
3. If the legacy server-side Drive OAuth is ever reactivated, it needs a same-site API origin and Google client secret. The former session cookie cannot be used from a cross-site `workers.dev` frontend fetch. Do not advertise that route as a connected Drive flow.
4. The configured Cloudflare Rate Limiting bindings protect public downloads and one-shot OAuth starts. If a required download binding is absent, `/download` returns 503.
5. The browser Drive button asks for Google consent only after a user click. GitHub and Notion use top-level OAuth navigation; Dropbox uses its provider popup. The app does not silently send a graph to any provider.

The legacy server-side Drive OAuth flow uses a 10 minute encrypted state/PKCE cookie and a short-lived encrypted, Secure, HttpOnly, SameSite=Lax token cookie. It is not called by the public UI. The live browser Drive button gets a short-lived token after a user click, uploads directly to Google, and does not persist that token. Users can revoke access in their Google Account.

## Route contract

Base path: `/api/integrations` on the deployed Worker. All JSON responses use `Cache-Control: no-store`. OAuth/status CORS allows credentials only from the exact `ALLOWED_ORIGIN`. The public `/download` file has wildcard CORS and no credentials so the provider widgets can fetch it; possession of its URL already reveals the graph content. The one-time GitHub/Notion flows use top-level navigation and short-lived, encrypted `__Host-` cookies on the Worker origin, not cross-site browser session cookies. Neither access nor refresh tokens are persisted.

- `GET /status` → provider availability for Worker-managed routes. Its `drive.available` refers only to the dormant server-side Drive route and stays false without Google Worker secrets; the live browser Drive button is independent of this field. `notion.available` and `github.available` reflect their Worker routes. No secret or OAuth token is returned. A top-level `download` field is true when the exact HTTPS origin and both download limiters are configured.
- `GET /download?graph=<encodeURIComponent(JSON.stringify(graph))>` → `200` with actual graph JSON, `Content-Type: application/json; charset=utf-8`, `Content-Disposition: attachment; filename="atom-graph.json"`, and `Cache-Control: no-store`. No cookies or Origin are needed for provider fetches; wildcard CORS plus `OPTIONS` support allows Save to Drive to fetch the public file. The sole query parameter must be `graph`; the URL is capped at 8192 characters and decoded and normalized graph JSON at 4096 UTF-8 bytes. Structural graph limits match `/exports`. `429 rate_limited` when either Cloudflare rate limiting binding denies the request; `503 download_unavailable/missing_config` without a valid `ALLOWED_ORIGIN` or both bindings; `414 url_too_long`, `413 graph_too_large`, `400 invalid_graph` or `400 invalid_request` for invalid input. No persistence or outbound fetch occurs. This URL is public and exposes the graph to anyone who obtains it, including the selected widget provider. The frontend should create it only after the user chooses that provider.
- `GET /oauth/github/start?graph=...` → `302` to GitHub with only the `gist` scope. Requires `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, `SESSION_SECRET`, `API_ORIGIN`, and `OAUTH_LIMITER`; otherwise `503`. The graph must have at least one expression and fit within 1,800 UTF-8 bytes. The Worker seals it with a random state in an HttpOnly, Secure, SameSite=Lax cookie for ten minutes. Its callback exchanges the single-use code, creates exactly one unlisted Gist containing `atom-graph.json`, clears the cookie, and renders a link to the Gist. The token never enters the site or response. The `gist` OAuth scope gives read/write access to the user's Gists, so the user must consent on GitHub's authorization screen.
- `GET /oauth/notion/start?graph=...&parent=<32-hex-page-id>` → `302` to Notion's user OAuth page picker. Requires `NOTION_CLIENT_ID`, `NOTION_CLIENT_SECRET`, `SESSION_SECRET`, `API_ORIGIN`, and `OAUTH_LIMITER`; otherwise `503`. The callback creates a child page under the exact parent supplied by the user, only if that page was selected for the connection and the user can edit it. Access and refresh tokens are discarded after that one page creation. The Notion connection remains authorized until the user revokes it in Notion. The public status endpoint does not advertise Notion until `NOTION_PUBLIC` is explicitly set to `true` after a live consent/export check.
- `GET /oauth/drive/start` → `302` to Google's consent page with a state and S256 PKCE challenge. Use top-level navigation. `503 {"error":"provider_unavailable","reason":"missing_config"}` if not configured.
- `GET /oauth/drive/callback` → Google redirect URI. Validates state and exchanges the code, then `302` to `${ALLOWED_ORIGIN}/proof-lab#graph`. `400 oauth_invalid` for invalid state. Tokens never enter the redirect URL.
- `POST /exports` with `Origin: <ALLOWED_ORIGIN>`, `Content-Type: application/json`, `X-CSRF-Token: <status.csrfToken>`, cookies, and body `{"provider":"drive","graph":{"v":1,"expressions":[{"expression":"y=x^2"}]}}` → `201 {"provider":"drive","id":"<Drive file id>","url":"https://drive.google.com/file/d/<id>/view"}` after Drive confirms creation. The graph is a JSON file in the consenting user's Drive, private by default. Body maximum is 16 KiB; graph follows the bounded public graph state fields. Missing OAuth: `401 not_connected`; bad origin or CSRF: `403`; bad graph: `400`; oversized body: `413`; Drive failure: `502 provider_error`; missing Drive config: `503 provider_unavailable/missing_config`; Notion/GitHub/Dropbox/Zapier: `501 provider_unsupported/unsupported`.
- `POST /oauth/drive/disconnect` with the same Origin, CSRF header and cookies → `200 {"provider":"drive","connected":false}` and clears the local token cookie. This does not revoke the Google token remotely.
- `OPTIONS /exports` and `OPTIONS /oauth/drive/disconnect` → `204` for the allowed origin; `403` otherwise.

The Worker never accepts a destination URL, arbitrary provider endpoint, raw access token, or service account credential from the request. Provider HTTP responses are bounded before parsing. The graph payload is structurally validated; it is not re-parsed as math, and the exported JSON is data, not an evaluated expression.
